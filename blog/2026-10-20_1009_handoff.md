# Handoff, 2026-10-20 10:09 UTC

Everything is built and validated on **simulated data only**. The Android app compiles and has JVM unit tests; it has
never run on a phone. Nothing has been run on a real building.

## Cloning on your PC (Android Studio)
1. `git clone https://github.com/dylankainth/wifiradar && cd wifiradar`
2. Open the `android/` folder in Android Studio (SDK platform 36; JDK 17+; Studio creates `local.properties`). Gradle 8.14 wrapper, AGP 8.13.2, Kotlin 2.2.21.
3. If Maven Central returns 429: `export WALLMAP_MAVEN_MIRROR=https://maven-central.storage-download.googleapis.com/maven2/` (see `android/README.md`).
4. CLI: `./gradlew assembleDebug` then `adb install -r app/build/outputs/apk/debug/app-debug.apk`; tests: `./gradlew testDebugUnitTest` (18 pass).
5. Python side: install `uv`, then `uv sync && make test` (36 tests, ~30 s).

## What exists
- `sim/` simulator, `solver/` pipeline (PDR, BSSID grouping, pose graph, AP localisation, OMP + JAX wall fit, export), `eval/` metrics/plots/sweeps/overlay,
  `android/` logger, `docs/` (data format, survey guide, ground-truth format, design), `README.md` (results + limitations).
- Run: `make sim`, `make solve`, `make fakereal`, `make sweep`, `make calibration`; real data: `uv run solver run --session data/X --truth ground_truth.yaml --step-length 0.70`.

## Headline results (8 held-out simulated houses)
- Trajectory error at markers: 3.3 m (PDR) -> 0.63 m (pose graph + fingerprint loop closure).
- AP error inside flat ~0.74 m. Wall F1 (observable walls, 0.5 m) 0.52 +/- 0.11; 0.79 at 1 m; 0.33 over all walls.

## Known limitations / honest caveats
- RSS cannot see the outer shell (power offsets absorb it); only ~1/3 of wall length is observable in the test flat.
- Walls are coarse (0.5-1 m off). Bootstrap confidence is weak (AUROC 0.5-0.72). Manhattan angle is not identifiable at this data volume.
- RTT benefit not demonstrated (2 simulated anchors: within noise). Odometry scale is not observable from loops: calibrate step length.
- Simulator and solver share assumptions; real data will do worse.
- Android glue (sensors, WifiManager loop, RTT, service, UI) is untested on hardware; checklist in `android/README.md`.

## Your next steps
1. Build/install the APK; phone setup per `docs/survey-guide.md` (Developer options, **Wi-Fi scan throttling off**, permissions, My APs).
2. Place numbered floor markers, tape-measure walls/markers/APs into `ground_truth.yaml` (`docs/ground-truth.md`).
3. Calibrate step length (10 m walk, count steps).
4. First walk 5-10 min with loops/revisits; check `meta.json` (`scan.median_period_s` << 20 s, `sensors.acc.achieved_hz` ~ 50).
5. Export from the app, unzip into `data/<name>/`, run the solver + overlay, send `result.json` and plots if odd.
